# 書き込む作業を、元の場所から切り離す

声で「スライド作って」「サイト直して」と頼むと、作業員がその場所で直接書きます。
気に入らなかったときに戻す手立てがありません。ChatGPT のエージェントが使い捨ての
仮想マシンでやっているのと同じことを、手元でやります。

## 2 通りあります

| 渡す先 | どうするか | 元は |
|---|---|---|
| git のリポジトリ | `git worktree` で別の場所に切る | **無傷。** 差分は patch で受け取る |
| git でない場所（Documents など） | `~/Koach/work/<名前>-<時刻>/` を作って、そこを作業場所にする | 読むだけ |
| 場所が分からない | **断る** | — |

⚠️ **切り離せないときは書き込みを断ります。** 元の場所で直接書かせません。
「隔離できなかったので、そのまま書きました」がいちばん困るからです。

## 読むだけのときは切り離しません

`write: false` の作業は元の場所をそのまま見せます。切り離すと、未コミットの変更が
入らないぶん、作業員が読むコードと実際のコードがずれるからです。

## 終わったとき

worktree のときは、**畳む前に差分を取ります**。

```
git add -A                                  ← 新しいファイルも見えるように
git -c core.quotepath=false diff --cached HEAD
```

⚠️ `add -A` が要るのは、`git diff HEAD` が追跡されていないファイルを含まないためです。
モジュールを 1 つ足しただけの作業が「何も書き換えていません」に見えて、成果物ごと
畳んでしまいます。

⚠️ `core.quotepath=false` が要るのは、既定だと日本語のファイル名が
`"\346\216\210\346\245\255.md"` のような 8 進表記で出るためです。差分を読むのは
機械だけではありません。「第3回.md」が読めないと、何が作られたのか分かりません。

差分は patch として `~/.../ariya-worktrees/<名前>.patch` に残り、作業ツリーと枝は
畳まれます。**patch を当てるのは本人です。** 当てなければ、元には何も起きません。

## フォルダ方式の限界

git でない場所は、cwd を新しいフォルダに移すだけです。**作業員が絶対パスで元の場所へ
書くのを止められません。** git の場所ほどの保証はない、と分かったうえで使ってください。

止めたいときは `~/.claude-code-app/control-off` を置けば、書き込みが全部断られます。

## 確かめ方

```sh
node --test test/isolate.test.js test/isolate-git.test.js
```

`isolate-git.test.js` は本物の git を使って、作業ツリーで書き換えても元が変わらないこと、
未コミットの変更が持ち込まれないこと、畳めば元に戻ることを通しで見ています。
